# كلمات — Arabic Crossword

نسخة تأسيسية للعبة كلمات متقاطعة عربية حديثة، RTL-first، مبنية لتتوسع من أول 100 وحدة إلى 1000+ وحدة.

## الموجود حاليًا

- واجهة عربية RTL ومتجاوبة للموبايل والديسكتوب.
- مسار من 100 وحدة.
- أول 10 وحدات قابلة للعب الآن، 15 مدخلًا لكل وحدة (150 سؤال/جواب seed).
- محرك توليد شبكة كلمات متقاطعة بالعربية مع تقاطعات واتجاه أفقي RTL وعمودي من الأعلى للأسفل.
- حفظ تلقائي للتقدم.
- نقاط، XP، مستوى لاعب، streak ونجوم للوحدات.
- قياس إتقان منفصل لكل باب معرفي بأسلوب adaptive/Elo-like.
- مساعدات: كشف حرف وكشف كلمة.
- صفحة نتيجة وبطاقات «هل تعلم؟».
- صفحة ملف لاعب وإحصاءات حسب الباب.
- وضع محلي كامل عبر localStorage.
- تكامل Supabase اختياري للحسابات والمزامنة.
- مخطط قاعدة بيانات Supabase مع RLS.
- اختبارات أولية للـnormalization ولمتغيرات الشبكة.

## الأبواب

العلوم والطبيعة، الجغرافيا، التاريخ والحضارات، الإسلام والحضارة، الأدب والشعر، اللغة والأمثال، الرياضة، مطابخ العالم، الحيوانات والنباتات، التقنية والاختراعات، الفن والسينما، والثقافة العامة.

## تشغيل محلي

المشروع Static SPA ولا يحتاج build step:

```bash
cd arabic-crossword
python3 -m http.server 8080
```

ثم افتح:

```text
http://localhost:8080
```

> لا تفتح index.html مباشرة من file:// لأن ES Modules تحتاج HTTP server.

## الاختبارات

يحتاج Node.js 20+:

```bash
cd arabic-crossword
npm test
```

## تفعيل Supabase

1. أنشئ مشروع Supabase.
2. نفّذ `supabase/schema.sql` في SQL Editor.
3. انسخ `config.example.js` إلى `config.js`.
4. ضع **Project URL** و **Anon/Public Key** فقط:

```js
window.SUPABASE_CONFIG = {
  url: "https://YOUR_PROJECT.supabase.co",
  anonKey: "YOUR_PUBLIC_ANON_KEY"
};
```

لا تضع Service Role Key في المتصفح.

إذا بقيت القيم فارغة، التطبيق يعمل تلقائيًا محليًا ويحفظ التقدم في localStorage.

## المحتوى

المداخل الموجودة حاليًا هي **editorial seed content**، وليست بعد بنكًا نهائيًا موثقًا بالكامل. كل مدخل يحمل حالة تحريرية، والهدف قبل نشر الوحدات النهائية هو:

1. التحقق من المعلومة.
2. تدقيق العربية وتهجئة الجواب.
3. فحص الالتباس.
4. إضافة المصدر.
5. إضافة ترخيص/نسبة أي صورة.
6. معايرة الصعوبة.
7. اعتماد المدخل.
8. توليد شبكة الوحدة مسبقًا وQA عليها.

الهدف النهائي للمرحلة الأولى: **100 وحدة × نحو 15 جوابًا ≈ 1500 مدخل معتمد**، من بنك مرشحين أكبر لتسهيل التقاطعات الجيدة.

## التوسع بعد 100 وحدة

المعمارية لا تفترض حدًا أقصى 100. الخط التالي:

- content candidates من Wikidata / Wikimedia Commons / مصادر موثوقة أخرى.
- deduplication وArabic normalization.
- مراجعة تحريرية.
- اعتماد فقط بعد verification.
- pre-generation للشبكات.
- نشر الوحدات الجديدة.

المحتوى القادم من الإنترنت لا يجب أن ينتقل مباشرة إلى اللاعب.

## ملاحظات هندسية

- `canonical answer` يبقى بالتهجئة العربية الصحيحة للعرض.
- المطابقة تستخدم normalization مستقلًا.
- لا يتم دمج ة/ه أو ى/ي عشوائيًا في النص الأصلي.
- الشبكات الحالية تولد عند التشغيل كـMVP. قبل الإنتاج يجب pre-generate الشبكات المعتمدة وحفظها بعد QA.
- الصور والخرائط يجب أن تحمل source/license/attribution metadata.
